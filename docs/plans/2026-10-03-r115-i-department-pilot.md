# R1.15-I 部门试用交付执行计划

基线：H.2 `5280de63ba7b5f2bd2fbfe078e50ce6f360cc462`。分支：`release/2026-10-03-r1.15-i-department-pilot-handoff`。附件为本轮范围权威；不合并 main，不继续设计 UI，不执行真实账号、平台或云操作。

## 1. 起点与恢复

核对全部祖先、远端和工作区；建立私有 all-refs bundle、生产文件只读指纹和公开 checkpoint。隔离证据保存在被忽略的 `output/r115-i-execution-20261003`，真实业务证据仅保存在仓库外受限目录。压缩后依 checkpoint 和进度记录恢复。

## 2. 安装、启动及依赖

审查现有 H.2 安装包与路径规则，选择最小且可证明身份的交付方式。使用独立程序目录、新数据目录、独立 session/log/media/temp 和测试快捷方式。网络保护在 Main 启动前加载。验证首次启动、离线、缺账号/Key、正常退出和重启、包资源、浏览器依赖及错误提示。区分同机隔离验收、标准用户和新 Windows 电脑，未执行层级保留 NOT_RUN。

## 3. 新库员工普通 UI 路径

按产品实际导入字段制作合成模板和问题示例，通过安装版普通 UI 创建企业、预览错误、导入 Draft、编辑保存、重启恢复、导入素材、人工审核、查看发布阻塞、导出脱敏诊断。独立验证资料包导入后仍需审核。测试数据不继承历史账号、Jobs 或凭据，不用直接 SQL 写状态代替员工动作。模拟历史/Unknown 仅用于显式标注的只读显示检查。

## 4. 私有准备与原库限制

仅检查已存在的受保护副本，准备首批康一/抖音/头条/官网候选证据和 Owner 操作入口。只读核对两份缺失历史图片的全部引用、可信备份候选、恢复/退休方案的影响与回滚要求。保持五条退役凭据和全部原记录不变。原库升级继续 PENDING_OWNER_AND_BACKUP_REVALIDATION。

## 5. 部门包与现场资料

整理唯一安装包、开始说明、范围、员工图解、导入模板、问题处理、首日清单、摘要校验及完整手机可读图集。公开包仅含软件和合成示例；业务和账号清单私有。现场检查单以一位同事、一个企业、一条业务发布为目标，每个真实动作要求届时明确授权。

## 6. 最终验收与交付

发现首日阻塞时先复现、最小修复、focused tests；普通文档和截图不添加镜像测试。代码完成后一次完整回归、typecheck、lint、build/package，验证确切包身份和安装版完整员工路径。进行一次独立全分支审查，处理必要问题。root ready.md 内嵌 4–6 张本轮实际安装版合成截图。扫描源码、安装包、交付 ZIP、截图后推 I 分支/Candidate Tag/prerelease；实际核对 GitHub 图片渲染、远端 HEAD/Tag/文档/资产摘要。最后重验生产指纹和 clean 工作区。

## 验收与审查重点

- 新库试用 PASS 不代表原库完整恢复、真实平台或真实云 PASS。
- 每次 Main 启动前网络阻断且数据路径明确；不得触及原生产目录。
- 普通 UI 导入与审批可追溯；无 SQL 写入伪造审批、账号或 Job。
- 交付包离开源码目录仍可使用，截图/模板/说明一致且不含私密内容。
- 新电脑、标准用户、真实账号/云/发布未执行如实报告；main 保持 H。
- 公开与私有证据不混淆，不重复实现已有 H.2 能力。
