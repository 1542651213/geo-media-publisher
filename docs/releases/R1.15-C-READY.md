## 独立审查的五项 Important 修复

1. package grant 的 expiry 会在 UI availability、Main 授权和 awaited-call 后重新检查；过期授权不能继续写。
2. 只有原 PREPARED operation、没有 publish step、final count=0、没有 boundary/remote request/response/external ID 时，才原子恢复同一 SubmissionIntent；保留 attempt history，不创建新 job/revision/key/final claim。
3. maintenance 只有 local step=`SUCCEEDED` 且 remote Job=`succeeded` 才能显示成功终态或允许凭据轮换；remote 已成功但本地仍 DISPATCHING/OUTCOME_UNKNOWN 时保持可恢复。
4. maintenance 202/GET 核对精确 nullable job binding。缺少 binding 的非终态旧 journal fail closed；已有 local `SUCCEEDED`、remote `succeeded` 和既有读回证据的历史终态保持终态。
5. 最新 maintenance step=`FAILED` 时显示该步骤的终态错误，不回退到原 publication Job；remote `needs_attention` 保持 `NEEDS_RECONCILIATION`。

发布成功与公开内容 fidelity 独立：原 exact publish Job=`succeeded` 且返回可信同 scope `publicUrl` 即为 Publish Success；raw SSR、media 和 public readback 独立记录 `PublicContentVerified=PASS/FAIL/LIMITED`。fidelity warning 不撤销成功，也不授权重发。

## 正常操作 SOP

1. 在账号中心选择已配置的 Kangyi staging 或 production OfficialAPI 账号；Main 从 SafeStorage 读取 credential，并重新验证 health/capabilities、site、environment、kind、limits 和 writesEnabled。
2. 在发布窗口选择 Website 与 ARTICLE/CASE，明确填写需要的 summary/category/keywords 等字段；只选择已启用的同品牌图片或明确 universal 图片。
3. 点击准备后检查冻结的 source/scope/settings/images；任务必须处于 AwaitingConfirmation。Website 不接受 dry-run 代替确认。
4. 只有人工 confirmed final 才进入唯一 Scheduled/final submit。任务完成后查看 Publish Success 与独立 `PublicContentVerified` 状态。
5. 不使用通用 Retry 重跑 Website。NeedsReconciliation 只用 Website 原操作恢复；不换 key、不建替代对象。
6. maintenance 从原本地 Website job 发起。production normal 对象没有 purge 权限；retained media 不得绕过 API guard 删除。
