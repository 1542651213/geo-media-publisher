# 完整快照、隔离恢复与同事资料包

「高级功能 → 数据备份」提供三种不同用途的操作：

| 操作 | 内容与用途 |
| --- | --- |
| 仅备份数据库 | 在线 SQLite 备份，含数据库业务状态；不包含媒体、浏览器资料或凭据上下文。 |
| 创建完整快照并正常退出 | 刷新工作副本，停止后台执行，关闭浏览器和数据库；独立本地进程等待应用完全退出后复制整个 userData，并记录版本、迁移清单、每个文件大小和 SHA256。 |
| 导出选定资料包 | 选定企业、文章、图片及可选模板；供同事导入为新企业与 Draft，不包含账号、凭据、授权、发布任务或审核批准。 |

完整快照创建失败会标为 Incomplete，保留现场；不得把它当作可恢复备份。重新启动后先点击「校验完整快照」。校验会检查清单、文件完整性、SQLite 和路径边界；损坏、缺文件、缺加密上下文、目录链接和超前 schema 会被拒绝。

退出后备份进程仍可能短暂工作；此时重新启动同一数据目录会提示等待，避免复制时重新打开数据库或浏览器存储。进程异常中断后，下一次启动将保留失败快照并标记 Incomplete，允许重新安排新的备份，不覆盖旧文件。

旧安装数据可能保留 7 个已退役迁移编号；已从本地保留的历史 Release 源码逐文件核对 commit 和 SQL SHA256，清单保留这些记录，不重放旧 SQL。当前资源目录有 37 个迁移，私有副本共 44 条历史记录；未知编号和非兼容 schema 仍被拒绝。

「恢复到新隔离目录」创建新的目录，不覆盖当前生产库。恢复标记先于内容落盘；启动恢复副本后 Scheduler、自动恢复和外部写操作保持暂停。程序明确显示「隔离恢复 · 人工复核中」。Owner 核对企业、账号、媒体、未知请求和历史结果后，再另行处理上线。

本轮的恢复启动使用安装后的 EXE，并设置 `GMP_B01_ISOLATED_USER_DATA_DIR` 为页面返回的绝对目录；最后一级必须是 `b01-isolated-user-data`，目录必须独立且已存在。该变量仅用于隔离验收；不要指向原生产目录或用恢复副本替换原目录。

凭据解密依赖 Windows 用户及系统加密上下文。包含 Local State 不保证跨 Windows 用户或机器可用。本轮在同一 Windows 用户、完整关闭后的私有副本中，仅 21/26 条加密记录成功解密，5 条失败，原因未确认。原凭据及原目录均未改写；该项为 PARTIAL，不能据此承诺所有真实账号可以恢复。Owner 应保留失败副本，按指定账号的正常登录或安全凭据更新流程核对，不自动清理、重加密或迁移失败条目。

升级前正常关闭并保留完整的旧版本快照和旧安装包。回退应恢复关闭后的升级前完整副本，再运行与该 schema 匹配的旧软件；不能让旧软件直接打开 G 升级后的数据库。

同事资料包只能导入业务资料，导入为新企业与 Draft，仍需人工核对和审核。预览过期或文件改变时须重新预览。文件选择取消不产生导入；失败的资料包和恢复目录应保留用于定位。

本机备份和本地 Git bundle 都位于同一台电脑，不是异机备份。异机备份仍需 Owner 配置明确的私有目标。
