# R1.15-H.1 UI audit — before implementation

Audit baseline: `c2017994ef3df592fd17ffa009a56fbcca99796c`, R1.15-H Candidate, verified equal to local main, origin/main and the H Candidate tag on 2026-10-03. The working tree was clean before creating the UI Candidate branch. This audit precedes all product edits.

## Findings

| Area | Observed issue | Intended presentation change |
| --- | --- | --- |
| Color | `styles.css` has 395 distinct hex values; three supplementary stylesheets add independent blue/gray palettes. Navigation, buttons, AI tabs and operations tabs use separate blues. | One restrained purple brand palette; semantic green/orange/red remain distinct. |
| Typography | The four stylesheets contain 180 font declarations below 12px. Table bodies and account facts use 10–11px; secondary labels often have weak contrast. | Readable 13–14px body/table/form text, stronger secondary text and line height; small metadata reserved for diagnostics. |
| Spacing, radius, shadow | Panel, platform card, toolbar, modal and drawer rules repeat unrelated values. | Tokens for spacing, corner radius, borders, elevation, focus, motion and layer order. |
| Buttons | Toolbar and account diagnostic actions frequently share primary weight. | One main action per context; secondary/tertiary diagnostic actions and explicit danger treatment. |
| Home | Six equal metric cards mix published totals with human attention and failures. | Put actionable exceptions first, today's review/plan second, inventory and totals last. Use only current snapshot data. |
| Headers and tabs | Workspace, operations and AI pages use different title/action/tab patterns. | Consistent title, context, notice, filter and content hierarchy. |
| Accounts | Platform catalog, account identity and diagnostic information compete. Internal states and context details appear beside ordinary employee actions. | Clear account identity/company/auth/capability facts; diagnostic disclosure; explicit batch OFF. |
| Ownership | Current binding, suggested company, confidence and evidence share one paragraph; conflicts can be missed. | Separate confirmed/current binding from an unconfirmed suggestion; prominent conflict/no-evidence/low-confidence notices. Preserve explicit Main confirmation. |
| Publish | Human workflow and technical diagnostics are interleaved. Gate codes can dominate missing prerequisites. | Visible workflow steps, passed/missing/next-action explanation and folded diagnostic details. No gate or handler changes. |
| Owner | Engineering diagnostic rows dominate the page; inherited release checklist is not summarized. | What/why/risk/next action, with static H release obligations clearly identified as an Owner checklist, not a live verification result. |
| AI | Many configuration actions have equal emphasis; company, draft status and workload budget need clearer separation. | A restrained brand header and clear configuration/input/budget/draft/review sections. AI output remains Draft. |
| Jobs | Initial load is plain text. Status distinctions depend on tiny chips. | Meaningful loading skeleton, legible semantic badges and retained error/refresh/filter behavior. Preserve H paging and performance work. |
| Empty/error states | Generic no-data text and bare errors provide inconsistent next steps. | Reusable notice/empty/loading presentation with existing legal entry points and retry callbacks. |
| Forms/dialogs | Label, helper, input height, overlay, body/footer and focus styles vary. | Shared styles and keyboard/focus checks; secret inputs remain password controls. |
| Large files | App.tsx 110,751 bytes / 423 lines; V11Workspace.tsx 149,610 bytes / 876 lines; OperationsCenter.tsx 49,116 bytes / 355 lines; styles.css 65,894 bytes / 353 lines. Many lines contain entire JSX sections. | Move cohesive presentation modules while keeping hooks, state, IPC calls and callbacks intact. Retain dynamic CSS selectors. |

Inspected: UI_SPEC.md; App.tsx; V11Workspace.tsx; OperationsCenter.tsx; styles.css; operations-center.css; platform-connection.css; product-ai-center.css; AccountOwnershipReview.tsx; JobsBoard.tsx; HumanReviewCalibrationPanel.tsx; ProductAICenter; enterprise, backup and About pages. Historical UI_SPEC text does not supersede current platform or publishing policy.

## Frozen boundaries

Main, Preload, IPC contracts, database/schema/migrations, platform adapters and capability policy remain unchanged. So do final-submit one-shot, SubmissionIntent, PublishRecord, unknown-result handling, session identity, company binding, draft approval, frozen Jobs and batch OFF. Build identity may identify this UI Candidate without changing runtime policy.

Before/after evidence uses a closed synthetic fixture, actual installed H/H.1 software, identical window conditions and a network guard installed before Main startup. Production data, 28 historical account bindings, two missing historical media files and five retired credential records are excluded from all UI fixtures and edits.
