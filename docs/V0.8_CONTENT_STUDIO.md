# V0.8 AI Content Studio

## 目标

V0.8 建立企业级 AI 内容生产流水线。输入品牌、行业、城市、关键词和目标平台，输出可审计的平台独立内容版本，并保留任务、生成历史和版本关系。

## 已实现能力

- 企业资料输入：复用已有品牌资料，生成时使用品牌简介、主营业务、服务流程、售后边界和 AI 禁止声明。
- 城市关键词批量扩展：在 Content Studio 内输入多个城市和关键词，结果写入现有 `keyword_items`，重复项自动跳过。
- 内容主题规划：通过现有 AI Provider 生成主题摘要、内容角度、目标人群、要点和推荐平台。
- 一次生成多平台内容：支持微信公众号、知乎、头条、微博、抖音脚本和 B 站视频脚本六种已存在的平台 key，不新增平台、不改 Adapter。
- 平台差异化：每个平台拥有独立标题、结构、关键词布局、语气和内容类型；图文输出进入文章主记录/平台变体，视频脚本作为内容变体保存。
- 素材上下文：可选择已有 Media Assets 和视频素材，将素材标题、描述、标签及视频元数据作为生成上下文；不会复制素材，也不会创建发布 Job。
- 任务记录：`content_studio_tasks` 保存输入快照、Provider、Model、进度、用量、耗时、失败信息和来源文章。
- 历史与版本：`content_studio_versions` 保存每个平台的版本号、当前版本标记、内容字段、素材绑定和文章变体关联；重新生成会产生新版本，旧版本保留。
- 重启恢复：应用启动时恢复状态为 `running` 的 Content Studio 任务，已持久化的平台版本不会重复生成。

## 数据与边界

本阶段新增 migration：`packages/db/migrations/0006_v08_content_studio.sql`。

Content Studio 只负责内容生产和内容版本持久化，不负责发布。发布仍必须由已有 Job Queue 创建和执行，真实发布仍由现有 Adapter 完成，并继续写入 `PublishRecord`。本阶段没有修改 `packages/publisher`、Job Queue、Adapter Registry 或任何既有平台 Adapter。

## 验证重点

1. 使用 Mock Provider 验证六个平台输出的标题、结构、语气和关键词布局确实不同。
2. 使用迁移后的临时 SQLite 验证任务、文章、平台变体、版本历史和重新生成版本可恢复。
3. 使用 HTTP mock 验证 DeepSeek/OpenAI-compatible Provider 可解析主题规划和平台内容 JSON，并保留 usage。
4. 运行 `pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。

## 已知边界

- 主题规划和内容生成依赖当前 AI Provider 配置；未配置 DeepSeek 时可使用既有 Mock Provider 做本地验证。
- 生成完成不会自动发布，不会绕过登录、验证码、安全验证或平台审核。
- 视频脚本不会被伪装为视频文件，也不会自动生成视频 Publish Job；如需发布，应从现有视频素材中心进入既有发布流程。
