# 完整恢复与同事分享

完整快照用于同一 Windows 用户恢复。正常退出会停止 Scheduler、等待草稿与 AI 收口、关闭数据库和应用持有的浏览器，再由独立 worker 复制。只有文件哈希、数据库完整性、外键和迁移验证通过，且退出交接完成后，状态才是 Complete。失败现场保留为 Incomplete。

清单记录应用/交付版本、源码 SHA、构建时间、实际迁移记录与 Schema、文件大小与 SHA256、凭据及 Local State 引用、浏览器目录引用和创建时间。旧 V1 清单仍可读取。快照含私密信息，不能放入公开仓库或同事资料包。

“校验完整快照”只读验证清单和文件。SQLite 检查使用临时副本，避免给原归档写入 WAL/SHM。它不能证明另一个 Windows 用户能解密：SafeStorage 仍需要原 Windows 用户及系统安全上下文。复制 Local State 本身不构成跨用户迁移。

“恢复到隔离目录”只接受新空目录，禁止覆盖当前数据、正式 production 目录或原归档。恢复标记先于文件写入，普通启动会暂停自动执行、外部连接和云请求。托管素材路径只在新副本重映射；冻结 Job、SubmissionIntent 和 PublishRecord 不改写。Unknown 操作须人工核对，不能通过重建任务或自动重试解决。

回滚使用与旧 G 安装版匹配的 **升级前完整快照** 恢复到另一个目录。不要直接让旧程序打开 H 数据库。原 production 不参与演练；H 私有副本升级/重启/回滚的最终验收结果见 [H READY](../releases/R1.15-H-READY.md)。

H 安装版的合成数据完整快照、只读校验、隔离恢复及重启不重放均 PASS。原生产关闭副本的完整素材校验发现 **3 条历史测试素材记录引用 2 个已不存在的外部图片文件**，因此保留失败现场并停止该完整快照路径。H 当时检查的文章封面和 Job payload 字段为零，不能据此推断所有引用为零。

I 对匹配当前生产文件指纹的关闭副本只读检查全部 65 张表、867 列，发现 **5 项 Job 的 selected_image_asset_id、4 项 PublishRecord 的 selected_image_asset_id、4 项回执 JSON 匹配**（字段匹配数，不是 13 条不同记录）。这些发布历史关系必须保留；当前退休提案为 BLOCKED_REFERENCED_PUBLISH_HISTORY，不允许按“无用测试记录”直接删除、清空关联或重写回执。缺失原件也没有可认证替代内容摘要；不填充替代图片，不把完整私有恢复标为 PASS。详情仅在仓库外私有 Owner 决策预览。

另外完成的私有数据库升级/回滚演练使用逐文件 SHA256 一致的完整关闭目录副本，保留上述缺失引用：G 44 条迁移记录 → H 45 → 另一个升级前副本的 G 44；80 张业务表内容一致，SQLite integrity/FK 校验通过，H 重启及 G 回滚后凭据均为 21 可读 / 5 已分类历史失效且字节未变。迁移、日志和运行设置表不纳入业务行哈希相等断言。这个结果只证明数据库与已存在文件的升级/回滚，不替代受阻的完整私有素材恢复验收。Owner 需先从受信备份核对缺失素材，或另行授权处理明确无用的测试记录，再重新执行完整快照校验。

同事资料包只导出明确选择的企业业务资料、当前审核通过且无未提交编辑的文章、选定企业图片、可选模板和已核实/批准/未过期的事实。内部事实备注、授权、凭据、Cookie、StorageState、发布任务和历史记录不导出。导入创建新企业；文章为 Draft，事实未核实且未批准使用。Main 再次验证当前内容哈希，不能通过 Renderer 选择绕过审核。旧 V1 无 facts 的资料包仍兼容。

实际 H 员工路径已验证资料包导出/导入。导入事实可在事实资料页点击「核对并编辑」，检查内容后重新勾选批准；更新原事实记录而不是另建重复记录。

建议升级前、授权变更后及每日收工创建并校验快照。异地目标与加密口令尚未配置，本轮不上传，不自创口令。Owner 可在受控存储中加密保管 Complete 快照并记录 SHA256、原 Windows 用户和匹配安装包；离开本机前应实际演练读取与恢复。当前异地备份仅具备操作准备，不代表已执行或已验证跨用户解密。
