# V1.0 Internal Platform Automation Hub

基线日期：2026-08-21（Asia/Shanghai）

本版本面向单企业内部运营人员，不引入 SaaS 租户隔离。平台能力按真实接入方式记录在 PLATFORMS.csv 的 integration_mode 字段中；Adapter ready 不等于账号已连接，也不等于真实发布已通过。

## 能力分类

| 能力 | 含义 |
|---|---|
| API | 使用已确认的官方接口；没有 Adapter 或真实权限时仍保持 NotImplemented / WaitingForUser |
| OAuth | 使用现有官方 OAuth Adapter；本轮不改变抖音、Facebook Pages、YouTube、TikTok |
| BrowserAutomation | Playwright 打开官方后台，用户自己登录并保存加密 Session；本阶段只准备任务，不自动点击最终发布 |
| SemiAuto | 自动准备并打开官方入口，用户最后确认 |
| Manual | 只生成内容，人工复制或上传 |
| Blocked | 当前不可接入，不提供万能或绕过方案 |

## 第一批完成范围

知乎、百家号、新浪微博、搜狐号、企鹅号、哔哩哔哩已完成统一 Browser Automation 接入：

- connectAccount 打开真实 Playwright 浏览器，用户自行完成登录、验证码、短信或安全验证；
- completeConnection 保存加密 storageState，并将账号状态推进为 Connected；
- checkSession 检查已有 Session，失效时返回 Expired / NeedsLogin；
- openBackend 打开官方创作后台；
- preparePublish 生成持久化发布任务准备结果；
- publish 在本阶段只允许 Dry Run/准备，真实最终提交明确返回 USER_ACTION_REQUIRED；
- verifyPublish 没有公开且审阅完成的回查合同时保持等待用户，不伪造 External ID 或 URL。

## 安全与记录

BrowserSessionManager 通过安全 CredentialStore 保存 storageState；生产环境由 Electron safeStorage 加密，Renderer 不读取 Session 文件，也不保存明文 Cookie。Session 标识只写入 browserSessionIdHash。遇到验证码、风控或安全验证时暂停并等待账号所有者，禁止绕过、破解或模拟未授权账号。

PublishRecord 记录 publishMode、automationType、browserSessionIdHash、operator 和 verificationStatus。本轮没有真实平台发布证据，因此不能升级为 PublishPassed；平台和账号继续按 WaitingForUser / NeedsLogin 等真实状态展示。

- packages/adapters/semi-auto/src/index.ts：SemiAuto Adapter。
- packages/adapters/*/src/browser.ts：六个平台的独立定义和包入口。

- apps/desktop/src/renderer/App.tsx、apps/desktop/src/renderer/PlansPageV031.tsx：平台中心和发布模式 UI。
- tests/v10-platform-automation.test.ts：V1.0 核心自动化边界测试。

## 验证结论

本地代码验证通过：pnpm lint、pnpm typecheck、pnpm test（37 个测试文件、180 个测试）、pnpm build。测试覆盖能力声明、Session 加密/恢复边界、无 Session 的登录要求、Manual/OAuth 不回归、发布模式、账号状态和失败恢复。

真实账号登录、平台安全验证、低风险真实发布和外部回查仍属于用户操作门槛，详见 MANUAL_ACTIONS.md；未完成前项目状态保持 WaitingForUser。
