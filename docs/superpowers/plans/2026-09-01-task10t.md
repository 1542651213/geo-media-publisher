# Task10T Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Task10S confirmation exactly-once, atomic, migration-safe, and visibly failed without starting XHS or publication during setup failure.

**Architecture:** Keep SQLite migration discovery as the startup authority, and expose one repository transaction that binds confirmation persistence and one-shot authorization creation to the Task10S test-run identity. Add Main/service idempotency around that transaction and a synchronous Renderer in-flight guard; retain final-submit authorization as a separate, unchanged hard boundary.

**Tech Stack:** TypeScript strict mode, Electron 37, React 19, better-sqlite3, Vitest, electron-vite, electron-builder.

**Spec:** `docs/superpowers/specs/2026-09-01-task10t-design.md`

- Do not edit production `publisher.db`; use temporary fixture databases for migration and failure tests.
- Preserve Task10R exploration and Task10S final-submit guard behavior.
- Do not use `git add .`, `git add -A`, `git clean`, `git reset`, or `git restore`.
